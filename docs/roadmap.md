Заменяет `docs/roadmap.md`. Основание: аудит кода (июль 2026) + серия решений по геймдизайну.
Темп: 10–15 ч/нед. Все оценки часов и календаря — порядок величины, не обязательство.

## Вырезано из первоначального замысла — и почему

| Вырезано | Было в докам | Почему |
|---|---|---|
| Свободное перемещение (Divinity-style) | `combat_system.md` | float-координаты ломают детерминизм, нужный для сети |
| Гексы | обсуждение | не даёт выигрыша под этот скоуп, дороже в отладке и арте |
| Вертикальность (High Ground) | Сессия 3 | дёшево в домене, дорого в левел-дизайне/камере/арте — 3 из 4 частей задачи вне кода |
| Атаки по возможности | Сессия 3 | усложняет FSM и сетевой протокол, отдача низкая |
| Раздельная броня (физ/маг) | Сессия 3 | дёшево в домене, но требует баланса и UI — отложено до рабочей боевки |
| Элементальные поверхности | «идеи на будущее» | отдельный слой симуляции, не по силам первой версии |
| Нодовый движок диалогов + NPC-мир | `quest_system.md` (Kingdom Come style) | сотни часов на движок+редактор+тексты; несовместимо со скоупом |
| Ходячий хаб / хаб как локация | обсуждение (вариант C) | тянет NavMesh, вторую камеру, анимации ходьбы и — главное — репликацию позиций по сети (другой класс сетевой сложности) |
| Создание персонажа игроком | Часть 4 | несовместимо с сюжетом на трёх прописанных героях; экономит UI и сохранение |
| Матчмейкинг, список лобби, античит, миграция хоста | Часть 3 | не нужно для игры с друзьями по коду подключения |
| Персистентный инвентарь/лут/экономика | вариант B/C оболочки | кампания фиксированная, экипировка выдаётся по сюжету — 2-3 слота, не инвентарь |
| 5 типов урона + открытые сопротивления по каждому | сверка с расширенным документом | больше по объёму, чем уже отложенная раздельная броня; физический + один тип магического урона на первую версию, остальное — после Вехи 3 |
| Вероятностные статусы с цепочками взаимодействий (мокрый→шок легче и т.п.) | сверка с расширенным документом | балансировка формул поверх ещё не написанного кода; оставлен простой бинарный шанс статуса без взаимодействий |
| Статичные поверхности (вода/масло/порча) | сверка с расширенным документом | это элементальные поверхности в урезанном виде — по факту то же самое, что вырезано выше; отдельный слой правил размещения и взаимодействия с ИИ и путём |
| Delay Turn | сверка с расширенным документом | добавляет FSM-сложность ровно там, где строгая очередь и один герой на игрока её убирают |
| Несколько концовок, ветвящийся граф кампании, голосование в коопе за выбор | сверка с расширенным документом | превращает линейную кампанию в разветвлённую; выборы остаются, но влияют на флаги/текст, не на структуру миссий |
| Полная нейроозвучка как обязательное требование по ходу разработки | сверка с расширенным документом | амбиция полировки, не системная задача; переносится в Веху 6/Steam как опциональное украшение, не блокирующее закрытие вех |

## Критерии пересмотра плана (проверяемые пороги, не «оценим по ходу»)

- Веха 1 заняла больше 120 ч → убрать из среза второй тип врага и укрытия, оставить голый бой
- Веха 3 (сеть) превысила 250 ч → заморозить сеть, сначала докрутить соло-боёвку до Вехи 5
- Арт-эксперимент не дал пригодного героя за 40 ч → готовые CC0-риги для персонажей, генерация только для пропов (уже основной план, но это жёсткий стоп-сигнал, а не «попробую ещё»)
- Один бой регулярно длится больше 35 минут → меньше врагов или быстрее их ходы
- Плейтестеры не хотят начинать второй бой → не делать новые карты, чинить Веху 2 (боевая система), контент подождёт
- Одна карта делается больше 60 ч → сократить кампанию до 6 миссий вместо 10–12, усилить переиспользование модулей карт

## Веха 1 — Вертикальный срез
**Готово, когда:** один бой на капсулах запускается билдом от начала до конца: сетка, перемещение с тратой AP, атака, HP-бар, победа/поражение.
**Показать людям:** да — это первое, что видно на экране во всём проекте.
**Оценка:** 30–50 ч / 3–4 нед (первая реальная калибровка твоего личного темпа — дальше оценки будут точнее).

- [ ] Координаты — целочисленная сетка (`int x, y`), `Assets/Scripts/Core`
- [ ] 8 направлений движения: ортогональный шаг дешевле диагонального (условно 10 и 14), нельзя срезать диагональ через заблокированный угол
- [ ] BFS с ограничением по AP — зона досягаемости (используется и для подсветки, и для валидации хода)
- [ ] Линия видимости (Брезенхэм) — тесты в домене
- [ ] `MoveCommand` как данные, тратит AP
- [ ] 3 героя (капсулы), 2–3 врага, строгая очередь по инициативе
- [ ] Минимальный презентационный слой: клик по клетке → подсветка → ход; HP-бар; кнопка атаки
- [ ] Билд, который запускается и доигрывается до победы/поражения
- [ ] Чеклист ручного прогона (5–7 пунктов): бой стартует, ход переходит корректно, AP тратятся, победа/поражение показываются, нет краша за один полный бой

**Оценка:** 120–200 ч / 8–13 нед (сеть для новичка почти всегда дороже плана — держим в голове верхнюю границу).

- [ ] Netcode for GameObjects + Unity Relay, подключение по коду
- [ ] Server-authoritative: ходы валидируются на хосте, бросок крита — на хосте
- [ ] Один герой на игрока, в соло — все три у хоста (механизм уже заложен в Вехе 0)
- [ ] Отвал игрока: его герой переходит хосту тем же механизмом владения
- [ ] Явный отказ от миграции хоста, античита, матчмейкинга, списка лобби — зафиксировано как решение, не забыто
- [ ] Синхронизация FSM боя через RPC/NetworkVariables
- [ ] Плейтест минимум 2 раза с реальными тремя игроками

*Почему сеть здесь, а не раньше и не позже: боевые системы уже готовы (наценка сети на будущий код невелика, дальше в основном контент), и есть на чём мотивирующе поиграть с друзьями до того, как основной объём часов уйдёт в контент.*

## Веха 4 — Сюжетная оболочка
**Готово, когда:** есть переход бой → лагерь → вставка с выбором → следующий бой, минимальное сохранение прогресса кампании.
**Показать людям:** да, это первый раз, когда игра выглядит цельной, не набором арен.
**Оценка:** 60–100 ч / 5–7 нед.

- [ ] Экран лагеря — статичная 3D-сцена с кликабельными точками (герои, карта следующего перехода)
- [ ] Окна рассказчика: текст из данных + 2–3 варианта выбора, флаги
- [ ] Данные миссии/перехода как ScriptableObject (data-driven, не хардкод в коде)
- [ ] Минимальное сохранение: номер текущей миссии, состояние отряда (HP, экипировка), флаги выборов
- [ ] Экипировка — 2–3 слота, выдаётся по сюжету, без инвентарного UI
- [ ] Между миссиями HP восстанавливается частично (не полностью), плюс один дополнительный выбор награды или восстановления — без экономики расходников
- [ ] Bootstrap-сцена и точка входа/DI (сейчас в проекте нет ни одного `MonoBehaviour` вне `SampleScene`)
- [ ] Границы домена соблюдены: понятия «клетка», «позиция в бою» не проникают в код лагеря/выбора миссии (условие того, что ходячий хаб можно добавить позже без переписывания)

**Помечено «передаваемо» (тексты и структура вставок) — если товарищ возьмётся, снимается с тебя без изменения порядка вех.**

**Показать людям:** да, это уже полноценное прохождение целиком.
**Оценка:** 150–250 ч / 10–17 нед. Основной объём здесь — контент, не код; наценка от сетевого слоя (Веха 3) на эту часть минимальна.

- [ ] 10–12 боевых карт (плоские, с укрытиями), собранных на сетке из Вехи 1–2
- [ ] Тексты вставок и выборов по форме «дороги» (пролог → этапы пути → развязка) — помечено «передаваемо». Выборы влияют на флаги и текст, не на структуру миссий (без ветвления графа кампании — это осознанно урезано против идеи «нескольких концовок»)
- [ ] Каждая миссия строится по формуле: основная цель + источник давления + необязательная награда. Цель — один из 4 типов: уничтожить конкретную цель, продержаться N раундов, защитить объект, дойти до зоны эвакуации
- [ ] Баланс с конкретными числами: HP/AP/урон по героям и врагам, прогрессия по ходу кампании

- [ ] Расстановка врагов и типов боёв по картам — разнообразие целей и источников давления, не разнообразие систем
- [ ] Полный плейтест кампании с людьми из Части 3, минимум 2 захода

- [ ] Английский текст (перевод вставок и UI) — объём равен объёму текста Вехи 5, помечено «передаваемо»
- [ ] Целевая платформа и настройки билда под релиз
- [ ] Возрастной рейтинг, финальный чеклист полировки (баги, которые друг простит, здесь становятся отзывом)
- [ ] Обновления/патч-план после релиза

## Блок: помощник — что можно передать

Список составлен, распределение — по факту того, за что товарищ готов взяться; порядок вех при передаче не меняется, снимаются только конкретные пункты.

| Блок | Веха | Что конкретно |
|---|---|---|
| Тексты и сюжет | 4–5 | Вставки рассказчика, тексты выборов, диалоги у костра |
| Перевод | 6 | Английская локализация текста Вехи 5 |
| Арт | 2, 5 | Модели окружения/пропов через генерацию, доработка карт |
| Звук | 5–6 | Звуковые эффекты боя, музыка лагеря/боя |
| Баланс | 5 | Числа урона/HP по контенту (после того как система в Вехе 2 работает) |

## Итог по срокам

При 10–15 ч/нед и без учёта Вехи 6 (Steam) полная кампания-«дорога» с сюжетом и кооперативом — примерно 465–770 ч, то есть 8–13 месяцев. С финишем в Steam — плюс 80–150 ч и особая планка полировки на всех этапах. Это оценка после первой реальной калибровки (Веха 1), не до неё — числа заведомо точнее, чем 1500–2500 ч из первичного разговора, потому что скоуп уже урезан этим самым разговором.
