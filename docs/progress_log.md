# 📅 Журнал Прогресса Разработки (Progress Log & Changelog)

Этот документ содержит хронологию сессий, выполненных задач и решений в проекте **FantasyRPG**.

---

## 📆 2026-07-31 — Выполнение Вехи 0 (Инкапсуляция домена и Assembly Definition)

### 🎯 Выполненные Задачи:
1. **Инкапсуляция очков действия (AP):** Логика списания очков (`TrySpendAP`, `CurrentActionPoints`) перенесена из стейт-машины хода (`PlayerTurnState`, `EnemyTurnState`) внутрь сущности `Hero`, чтобы гарантировать долговечность состояния и независимость команд. Убран мертвый код из машин состояний.
2. **Инкапсуляция здоровья:** Свойство `CurrentHealth` вынесено из `HeroStats` напрямую в `Hero`. `HeroStats` стал полностью иммутабельным "паспортом" базовых характеристик персонажа.
3. **Детерминированный шанс крита (Seeded Random):** Генерация случайного числа для критического урона перенесена внутрь доменной логики `DamageCalculator`. Добавлен метод `SetSeed` для будущей поддержки автотестов и сетевой синхронизации кооператива (Веха 3). `AttackCommand` больше не принимает флаг крита извне.
4. **Assembly Definition:** Создан файл `FantasyRPG.Core.asmdef` для физической изоляции ядра игры в независимую сборку, что ускорит компиляцию и защитит архитектуру.
5. **Обновление правил агента:** В `.agents/AGENTS.md` добавлено правило для автоматического исправления агентом мелких синтаксических опечаток. Уточнено правило в `mentor_rules.md` по поводу использования абсолютных путей `file:///` в рамках IDE чата для их кликабельности.

## 📆 2026-07-30 — Design-валидация роадмапа и правка документации

### 🎯 Выполненные Задачи и Дизайнерские Решения:
1. **Валидация роадмапа во втором чате (второе мнение):** проведена серия вопросов по геймдизайну независимо от предыдущего чата. Полный новый роадмап — `docs/roadmap.md`, заменяет прежнюю структуру сессий 1–6.
2. **Ключевые решения:** линейная кампания 10–12 боёв (форма «дорога» с лагерем-хабом), окна рассказчика вместо нодовых диалогов, квадратная сетка с LoS без вертикальности, строгая очередь по инициативе с гибким распределением героев в коопе (не строго 1:1), сеть — третьей вехой (после того как боевка станет играбельной, до основного объёма контента).
3. **Явно вырезано и вынесено в `docs/roadmap.md`:** нодовые диалоги, ходячий хаб, вертикальность, свободное перемещение, гексы, атаки по возможности, полная матрица из 5 типов урона с открытыми сопротивлениями, Delay Turn, ветвящиеся концовки, создание персонажа игроком. `docs/quest_system.md` помечен как отложенный.
4. **Правка документации и правил под актуальный скоуп:**
   - `docs/README.md` переписан: убрано ложное «100% завершено» там, где это не подтверждено тестом; `docs/quest_system.md` перемещён из основных модулей в отложенные.
   - `project_wiki.md` (побайтовый дубль `docs/README.md`) заменён на редирект-заглушку.
   - `docs/combat_system.md`: диаграмма `ICombatCommand` исправлена под реальный код (в интерфейсе нет `APCost`), явно отмечено, что расход AP не подключён.
   - `docs/domain_model.md`: диаграмма `HeroStats`/`Hero` обновлена под целевой дизайн — `CurrentHealth` выносится из `readonly struct` на `Hero`, `Speed` разделён на `Initiative` и `MoveSpeed`.
   - `.agents/rules/mentor_rules.md`: правило проактивной документации переформулировано — обновлять доки после теста/билда, а не до; поправлена нумерация правил.
   - `.agents/rules/code_review_rules.md` и `.agents/rules/architecture.md`: требование `FastBufferWriter`/ручной бит-паковки смягчено до «встроенной сериализации NGO достаточно для 3 игроков, ручная — только если профайлер показал проблему».
   - `.agents/rules/game_concept.md`: полностью переписан — убран Quest & Rewards Subsystem и Event Bus как уже спроектированные готовые подсистемы, добавлена явная пометка «target design, not implemented yet» и ссылка на актуальный роадмап.
   - Все абсолютные ссылки `file:///C:/Users/shtil/OneDrive/...` во всех .md-файлах заменены на относительные пути.

## 📆 2026-07-29 — Аудит Архитектуры ИИ и Уточнение Плана

### 🎯 Выполненные Задачи и Дизайнерские Решения:
1. **Аудит состояния проекта:** 
   - Выявлено несоответствие документации и кода: `EnemyTurnState` оказался лишь каркасом выдачи очков действия без реального мозга ИИ.
2. **Планирование Utility AI & Пространства:**
   - Принято решение не использовать сторонние ассеты (Behavior Designer, NodeCanvas), а написать собственный Utility AI для соблюдения Zero-GC и Clean Architecture.
   - Запланировано внедрение координатной системы позиционирования (Divinity-style) с расходом AP на передвижение.
3. **Обновление Документации:**
   - В Сессию 3 официально включены задачи: **Пространство (Grid)** и **Умный ИИ Врагов (Utility AI)**. Все вики-документы синхронизированы.
