## 📆 2026-08-02 — Сетевой задел: разделение Speed → Initiative/MoveSpeed (Веха 0)

### 🎯 Выполненные Задачи:
1. **Первый пункт сетевого задела закрыт:** `HeroStats.Speed` разделён на `Initiative` (порядок хода, потребитель — `InitState.Enter()`) и `MoveSpeed` (клеток за 1 AP, потребитель — `MoveCommand` из Вехи 1, пока не написан). `MoveSpeed` явно помечен комментарием в коде как временно непотреблённый — осознанное отступление от `code_review_rules.md` §7 (property-to-logic consistency), а не недосмотр. Все вызовы конструктора `HeroStats` в тестах обновлены (`speed:` → `initiative:` + `moveSpeed:`). `dotnet test` — 9/9 зелёных.
2. **Модернизация синтаксиса (отдельные коммиты):** проект переведён на target-typed `new()` (C# 9+) везде, где тип слева однозначен; исключение — конструктор конкретного класса, передаваемый в параметр интерфейсного типа (`ChangeState(new PlayerTurnState(...))`), где `new()` не может вывести конкретный тип из интерфейса. Правило зафиксировано в `.agents/rules/architecture.md` §3.

## 📆 2026-08-01 — Тесты домена и билд-гейт без Unity (Веха 0)

### 🎯 Выполненные Задачи:
1. **Исправлено расхождение рефакторинга инкапсуляции:** `AttackCommand.CanExecute()` и `TurnBasedCombatEngine` (`CheckCombatEnd`, `AdvanceTurn`) всё ещё читали здоровье через устаревший путь `Hero.Stats.CurrentHealth`, хотя `CurrentHealth` был перенесён на `Hero` ещё 2026-07-31. Найдено `dotnet build` (см. пункт 2) как ошибка компиляции `CS1061`, исправлено на `Hero.CurrentHealth` напрямую.
2. **Билд-гейт без установленного Unity:** на рабочем компе нет Unity Editor/Hub (только .NET SDK 10.0.302). Заведён отдельный `Tests.Core/FantasyRPG.Core.Tests.csproj` — обычный dotnet-проект, который компилирует исходники `Assets/Scripts/Core/**/*.cs` и тесты `Assets/Tests/Core/**/*.cs` напрямую, без Unity. Это возможно только потому, что `Core` по архитектуре 100% независим от Unity (см. `docs/architecture.md`). Параллельно добавлен `Assets/Tests/Core/FantasyRPG.Core.Tests.asmdef`, ссылающийся на `FantasyRPG.Core`, — для проверки внутри самого Unity на домашнем ПК (не проверено на этом компе).
3. **Написаны и подтверждены зелёным `dotnet test` (7/7) юнит-тесты:**
   - `DamageCalculatorTests`: без крита (`critChance: 0f`), с гарантированным критом (`critChance: 1f`)
   - `HeroTests`: `TrySpendAP` — нехватка AP (отказ, AP не потрачены) и happy path (хватает, тратится); `TakeDamage` — обычный урон и смертельный (clamp к `0`)
   - `TurnBasedCombatEngineTests`: `AdvanceTurn` переключает `ActiveUnit` с игрока на врага
4. **Замечание на будущее:** NUnit 4.x вынес классические ассерты (`AreEqual`, `IsFalse`...) в `NUnit.Framework.Legacy`/`ClassicAssert` — если Unity Test Framework на домашнем ПК тянет NUnit 3.x, эти тесты могут потребовать правки `using`/имени класса ассертов при первом запуске внутри редактора.
5. **Обновлены `docs/roadmap.md` (чек-лист Вехи 0), `docs/combat_system.md`, `docs/domain_model.md`** — сняты пометки "не исправлено"/"целевой дизайн, не текущий" там, где поведение теперь подтверждено тестом, по правилу `mentor_rules.md` §10 (документ обновляется после теста, не до).
6. **Правило ментора:** добавлено явное исключение в `mentor_rules.md` — имена тестовых методов (`<Метод>_<Условие>_<Результат>`) даёт агент напрямую, без наводящих вопросов, поскольку это не несёт обучающей ценности.
7. **Уборка репозитория (агентские файлы и доки):** `docs/quest_system.md` переименован в `docs/quest_system.deferred.md` (пункт чек-листа Вехи 0 закрыт, все ссылки на файл обновлены); `.antigravity/settings.json` (личная настройка IDE) убран из git-трекинга и добавлен в `.gitignore`. Unity-сгенерированные файлы (`Assets/TutorialInfo/` и т.п.) сознательно не тронуты в этом заходе.

### ⚠️ Не проверено / оставлено на потом:
- Компиляция `FantasyRPG.Core.Tests.asmdef` внутри самого Unity Editor — Unity не установлен на этом компе, нужна проверка на домашнем ПК.
- `.gitattributes` + Git LFS — не настроены.
- "Проект вынесен из OneDrive" — не проверяемо с этого компа, уточнить состояние на домашнем ПК.
- Сетевой задел (`OwnerId`, ID-based юниты, `ICombatCommand` как сериализуемые данные, разделение `Speed` → `Initiative`/`MoveSpeed`) — не начат, следующий кандидат на шаг.
