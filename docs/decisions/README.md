# Architecture Decision Records

Каждый файл — решение по одному конкретному техническому или геймдизайнерскому вопросу,
зафиксированное с альтернативами и причинами отказа от них. Неизменяемы после принятия:
изменившееся решение — это новый ADR со ссылкой «Superseded by ADR-000N», не правка старого.

Статусы: `Proposed` (обсуждается) / `Accepted` (решено, реализация не обязательно начата —
статус кода живёт в `docs/roadmap.md`, не здесь) / `Superseded`.

| № | Решение | Статус |
|---|---|---|
| [0001](./0001-pathfinding-bounded-dijkstra.md) | Bounded Dijkstra + compact open-set для перемещения по сетке | Accepted |
| [0002](./0002-action-points-and-movement-economy.md) | Единая AP-экономика и стоимость перемещения (`Movement`) | Accepted |
| [0003](./0003-movement-legality-occupancy-and-diagonal-corners.md) | Легальность перемещения, занятость клеток и диагональные углы | Accepted |

## ⚠️ Не собирай текущее состояние из ADR — для этого есть спека

ADR неизменяемы **намеренно**: каждый точен относительно момента принятия, включая
рассмотренные тогда альтернативы. Переписывать их нельзя — это сломало бы аудиторский
след, ради которого они и заводятся.

Следствие: контракт `Pathfinder` **дописывается** между ADR, а не правится в исходном.
ADR-0001, прочитанный отдельно, выглядит актуальным, но его сигнатура и предикаты уже
расширены в ADR-0002 и ADR-0003.

**Поэтому текущее состояние перемещения живёт в отдельном перезаписываемом файле:
[docs/movement_spec.md](../movement_spec.md).** Начинай с него; ADR читай, когда нужно
«почему так» или список отвергнутых альтернатив.

| Вопрос | Куда идти |
|---|---|
| «Как устроено сейчас» | `docs/movement_spec.md` |
| «Почему так решили, что отвергли» | соответствующий ADR |
| «Что уже написано в коде» | `docs/roadmap.md` |

Разделение обязанностей: ADR — журнал решений (неизменяем, растёт числом), спека —
текущее состояние (одна, перезаписывается). Любой новый ADR, меняющий перемещение,
обновляет спеку **в том же коммите**. Расхождение — баг спеки: ADR первичны.

Правило для будущих ADR остаётся: ADR, меняющий входы или результат `Pathfinder`, обязан
содержать раздел с **полным** актуальным контрактом, а не только локальную поправку.
